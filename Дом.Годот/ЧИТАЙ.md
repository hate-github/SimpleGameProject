# Дом.Годот — сборка движка

Проект Godot 4.4 на C#. Заведён на **этапе 3** переезда
(`docs/ПЕРЕЕЗД.md`), когда ядро уже сошлось с эталоном, а в консоли
сыграны тридцать дней руками.

## Как запустить

```bash
dotnet build ../Дом.sln          # соберётся и без Godot
```

Игру запускает сам Godot 4.4: открыть эту папку как проект и нажать F5.
Godot нужен только для запуска — **весь код узлов проверяется обычной
сборкой**, потому что `Godot.NET.Sdk` приходит с NuGet. Разделение
полезное: ошибка в C# видна сразу, а не «когда дойдут руки открыть
редактор».

## Что здесь есть

```
ДомУзел      корень сцены: держит партию, раздаёт её экранам
ПодъездUI    план подъезда: кто где, что светится, откуда дым
ЖурналUI     лента дня со временем
ВопросUI     экран выбора — те же оценённые варианты, что видит NPC
СостояниеUI  шесть шкал, шкаф и что я знаю о соседях
ТелефонUI    чат подъезда (ГДД 19, первое приложение)
Пути         где движок берёт data/*.json
```

Интерфейс собирается **кодом**, а не сценой, и это выбор. Сцену нельзя
ни собрать, ни проверить без редактора; код узлов проверяется `dotnet
build`. Когда дойдут руки, любой экран разбирается в `.tscn` без единой
правки логики — она вся в `Дом.Экран`, куда сцены не заглядывают.

## Направление зависимостей

```
Сцена Godot → Дом.Годот → Дом.Экран → Дом.Ядро
```

Только вниз, и это проверяется, а не подразумевается: `Дом.Консоль
проверить`, раздел «граница движка», читает все csproj и краснеет
на ссылке вверх. Он же считает упоминания Godot в `Дом.Ядро`
и `Дом.Экран` — там их ноль.

- `Дом.Ядро` — симуляция. Зависимостей нет вовсе.
- `Дом.Экран` — что показывают игроку, записями. Без Godot: те же записи
  печатает консоль, и потому слой проверяется прогоном без движка.
- `Дом.Годот` — сцены, узлы, ввод, интерфейс.
- `Дом.Консоль` о движке не знает.

Простая проверка границы: **сутки должны считаться из консоли, без сцены
и без рендера.** Если для этого понадобится `SceneTree` — граница нарушена.

## Симуляция и кадры

Симуляция синхронна и обязана такой остаться: она перенесена с Python
дословно, и переделка под `async` переставила бы вызовы, а с ними —
броски `rng`. Но `_Process` обязан вернуться, иначе окно замрёт.

Развязка — `Дом.Экран.Партия`: дом считает на своём потоке и **засыпает
на вопросе**, экран живёт на своём и его будит. Ни одной правки в ядре
это не потребовало.

Проверяется без движка: раздел «партия» гоняет ту же жизнь дважды —
на потоке и в один поток — и сверяет дома каноническим снимком. Мост
ломается тихо (потерять вопрос, ответить умолчанием, переставить два
ответа), и снимок ловит каждый такой случай.

Отсюда же: частота решений не зависит от FPS. В прототипе она вообще
не зависит от времени — и не должна начать.

## Что здесь будет и чего здесь не будет

Будет: пространство, звук, шрифты, привязка «жилец → внешность»,
`Resource` для моделей и материалов.

Не будет: нужд, памяти, знания, отношений и решений. Ни один узел за них
не отвечает. Если ради интерфейса захочется положить решение в `Node` —
значит, не хватает адаптера, а не архитектуры.

Отдельно: **баланс, жильцы, события и реплики остаются JSON**
(`data/*.json`) и читаются ядром напрямую. В `.tres` их не переводить —
это убьёт двустороннюю проверку ручек и рассыплет настройку по редактору.

# Прототип «Дом на 6 соседей» — памятка для сессии

Детерминированная симуляция подъезда в метель: Python 3.12, без зависимостей,
`house/` — домен, `data/*.json` — баланс и жильцы, `check.py` — вся проверка.
Идентификаторы и комментарии — по-русски; комментарии — документация проекта,
при переносе кода они переезжают вместе с ним.

## Рефакторинг по аудиту: восемь задач сделаны, правила остаются

- Аудит: `аудит_архитектуры.md`. План по задачам: `docs/REFACTOR_PLAN.md`
  (одна задача — одна сессия; читать только «Что читать» задачи).
  Решения: `docs/ARCHITECTURE_DECISIONS.md`. Запись о сделанном: `ПЛАН.md`,
  раздел «План восьмой: архитектура». План поведения NPC сделан:
  `docs/BEHAVIOUR_PLAN.md`. Дальше — план агента: `docs/AI_BEHAVIOUR_PLAN.md`
  (одна фаза — одна сессия; фазы 0–3 сделаны: проверка чтения правды, ADR-10,
  база `docs/измерения/до-агента/`, утечки закрыты знанием, `Самочувствие`,
  разбор решения; запись — `ПЛАН.md`,
  «План десятый». Счётчики `h.stats` на N зёрнах: `docs/измерения/счётчики.py`).
- Правило: один коммит — одна правка, `python check.py` зелёный **без**
  `--золотой`. Перестановка `rng` или строка журнала — отдельный коммит
  с `--золотой` и абзацем в `ПЛАН.md`.
- Не читать целиком README (1 800 строк), ПЛАН (3 600), `actions.py` (3 200).
  Оглавление модуля: `grep -n "^def \|^class \|^[А-ЯA-Z_]\+ = " house/x.py`.
- Многоагентные прогоны не запускать: проверка — `python check.py`.
- Действие живёт в трёх местах: запись `Действие(...)` в `catalog.ДЕЙСТВИЯ` (таблицы
  `COST`, `НОРМА`, `ТЕГИ` и прочие собираются из неё), исполнитель `@исполняет("ключ")
  def _исполнить_ключ(h, npc, target, spent)` в `actions.py` — возвращает текст строки
  журнала или `НЕ_СОСТОЯЛОСЬ`, — и оценка `корзина.add(...)` в одном из разделов
  `gather` (`_быт` … `_себя`). Часы — `часы_действий` в `balance.json`. Полнота
  сверяется при импорте.

## Карта house/

`engine` — оркестрация дня (141 строка: `run`, `one_day`, утро, день, сутки);
`assembly` — сборка из JSON; `schema` — чтение и проверка данных; `catalog` —
записи действий; `actions` — выбор (`gather` и разделы) и исполнители;
`street` — за порогом квартиры; `household` — сожительство; `services` —
услуги; `night` — ночь и её оценки; `psyche`, `physiology`, `child` — утро
и сутки человека и ребёнка; `discoveries` — утренние обнаружения; `social`,
`conflict`, `meeting`, `замысел`, `chat`, `world`, `model`, `character`,
`report`, `checks`, `runner`, `util` — как и были; `hooks` — наблюдатели
(`Хуки`, `наблюдаемо`), которых дом зовёт сам; `decision` — шов решения
(`Решающий`: `Софтмакс`, `Скрипт`, `Человек`).

## Проверка

```bash
python check.py                 # ~2 минуты: данные, ручки, инварианты, детерминизм, эталон по дням
python check.py --прогонов 120  # раз в задачу: мёртвые ветки на надёжной выборке (и все линейки)
python check.py --линейки       # плюс каждая линейка на одном зерне
python check.py --золотой       # только осознанно, см. правило
```

Один seed, ~3 с: `python -c "import check; print(check.отпечатки(3)['итог'])"`.
Расхождение с эталоном печатается как «зерно N: с дня M: разошёлся журнал /
только состояние».

## Технические мелочи

- Файлы на диске в CRLF (`core.autocrlf=true`), в репозитории — LF: править
  через Edit или Python с `newline=""`; длинные heredoc в Git Bash ломаются.
  `grep $'\r'` в Git Bash CRLF не видит — проверять байтами из Python.
  Скрипт-переносчик делит строки по `\r\n|\r|\n`, как Python, а срезы внутри
  строки берёт **в байтах**: `col_offset` у `ast` — смещение в UTF-8, и на
  кириллице символьный срез уезжает вдвое.
- Решение читает чужое только через знание: `check.проверить_чтение_правды`
  красит чтение поля из `ПРАВДА` (тело, шкаф, чувства, отношения, память,
  `power()`, `days_of()` …) у не-решающего имени в функциях из `РЕШАЮЩИЕ`.
  Допустимое чтение — пометка на той же строке `# правда: причина`, причина
  начинается словом из `ПРИЧИНЫ` (исполнение, под одной крышей, общее знание,
  видно, событие было со мной, квартира, решение автора, фаза 1). Новая
  решающая функция — строка в `РЕШАЮЩИЕ`; помощник, читающий тело переданного
  человека, — в `ЧИТАЮТ_ТЕЛО`. Что считается общим знанием — ADR-9 и ADR-10.
- Линейки (`замер.py`, `поводы.py`, `своё.py`, `снаружи.py`, `живость.py`,
  `вдвоём.py`) и `checks.Coverage` — наблюдатели через `h.hooks` (`house/hooks.py`):
  `Simulation(hooks=Хуки(on_execute=[f], …))`, `runner.many(hooks=…)`. Функции
  домена не подменять; новая точка — поле в `Хуки` плюс `@наблюдаемо("имя")`
  на функции с `h` первым аргументом (или `h.hooks.зов("on_имя", …)`). Наблюдатель
  ничего не меняет и не трогает `h.rng`; `h.hooks` в снимок не входит.
- Вся случайность — через `h.rng` (`util.Rng`); порядок вызовов — часть
  поведения. Множества перебирать через `sorted`.
- `check.проверить_ручки` ищет чтения ручек баланса по всему тексту `house/*.py`,
  включая докстринги: квадратные скобки с ключом в кавычках в комментарии —
  это «отсутствующий ключ». Писать про ручки словами.
- `python check.py | tail` прячет код выхода: писать вывод в файл и смотреть `$?`.
- Жив и в доме — `p.здесь()`, по id — `h.живой(id)`; ценности — `p.ценит(...)`,
  `p.не_терпит(...)`. Смерть — только `conflict.умер(...)`: он ставит поля и зовёт
  `on_death`, свидетелей считает вызывающий.
- Состояние — с типом: на день — `h.сутки` (новый объект в `новый_день`), очереди
  на утро — `h.ожидает`, даты и погода — `h.календарь`, остальное — поля `House`
  и `NPC` с умолчанием. Записи (`Ребёнок`, `Тело`, `Заказ`, `Замысел`, `Обещание`,
  `Ложь`, `Память`, `Приговор`, `Дежурство`, `Взгляд`, `Сведения`) и перечисления (`Оружие`, `ВидКладовой`,
  `Режим`, `Ночь` — `StrEnum`, равны своим строкам) — в `model.py`. Новое поле
  попадает в снимок само и меняет эталон.
- Как человек себя чувствует — `actions.самочувствие(h, npc)` → `Самочувствие`
  (`model.py`): одна запись на ход, её получают все разделы `gather` и ночь.
  Новая нужда — поле в записи, а не переменная в шапке; запись чистая
  и `h.rng` не трогает.
- Решение — через `npc.решающий` (`house/decision.py`): правила собирают оценённые
  варианты и зовут `день`/`ночь`/`ответ`; монета NPC — `decision.монета`, правило —
  `decision.по_правилу`. `gather` отдаёт `Корзину` (варианты — в `.варианты`,
  их получают и наблюдатели `after_gather`), а с ней объяснение: `слагаемые`
  оценки, `отказы` с причиной и самочувствие. Копится только при
  `Решающий.разбирает` (скрипт и человек, не softmax) — печатают его
  `decision.объяснить` / `состояние` / `закрытое`. Новое решение жильца не бросает `h.rng` само и не сравнивает
  мерку с нулём — оно задаёт вопрос решающему, иначе игрок его не получит. Что NPC
  знает о соседе — `npc.видит(id)` (`Взгляд`), `npc.сведения_о(id)` (`Сведения`),
  `believed`, `видимая_сила`, `видит_хворь`, `слышал(id, что, день)` (`Память`),
  `расположение_ко_мне(id)` — а не `t.stock`/`t.sick`/`t.power()`/`t.trust`; чужую
  цену со стороны считает `social.value_of(…, глазами=npc)`. `h.stats` — диагностика: решения её не читают
  (`check.py` красит любое чтение вне бухгалтерии), знание о расправах и кражах —
  `знает_убийств`, `знает_изгнаний`, `знает_о_кражах()`.
- Коммиты — маленькие, по-русски, в стиле `git log`; не пушить без просьбы.
